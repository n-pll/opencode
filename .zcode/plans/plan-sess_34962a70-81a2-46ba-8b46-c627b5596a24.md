# 给 ocl 加 --locale 参数

## 问题
CLI 的 locale 在 `packages/opencode/src/i18n/index.ts:14` **模块加载时**就 resolve 并冻结成闭包 `t`。而 yargs 参数解析更晚。ESM import hoisting 让 `index.ts` 顶层代码无法在 i18n import 前执行,所以普通的 yargs `--locale` 参数来不及影响翻译器。

## 方案:boot 模块提前设环境变量

新增 `src/boot/locale.ts`,其**顶层代码**在 index.ts 的第一个 import 时执行(ESM 深度优先、按声明顺序),早于 i18n import。它扫 `process.argv` 找 `--locale <code>` 或 `--locale=<code>` 或 `-L <code>`,设 `process.env.OPENCODE_LOCALE`。后续 i18n 模块加载时 `resolveLocale()` 读到这个 env,就用指定语言。

## 改动清单

### 1. 新增 `packages/opencode/src/boot/locale.ts`
```ts
// Resolve --locale/-L from argv before any i18n module loads, so the CLI
// translator picks up the requested language. ESM imports are hoisted, so
// this module's top-level code runs at import time (index.ts imports it
// first), before the i18n dictionary binding in src/i18n/index.ts executes.
for (let i = 2; i < process.argv.length; i++) {
  const arg = process.argv[i]
  if (arg === "--locale" || arg === "-L") {
    const value = process.argv[i + 1]
    if (value && !value.startsWith("-")) process.env.OPENCODE_LOCALE = value
    break
  }
  if (arg.startsWith("--locale=")) {
    process.env.OPENCODE_LOCALE = arg.slice("--locale=".length)
    break
  }
}
```

### 2. `packages/opencode/src/index.ts` 第一行
```ts
import "./boot/locale"   // 必须第一个 import,在 i18n 绑定前设 locale env
import yargs from "yargs"
...其余 import 不变
```

### 3. yargs 链注册 `--locale` 选项(让 --help 显示,并参与校验)
在 index.ts 的 `.option("pure", {...})` 之后加:
```ts
.option("locale", {
  describe: t("cli.global.option.locale"),
  type: "string",
  choices: ["en", "zh"],
})
.alias("locale", "L")
```
> 注意:这个 yargs option 主要是给 `--help` 显示用。真正生效靠 boot 模块提前设的 env。middleware 里不需要再处理。

### 4. i18n 字典(AGENTS.md 要求)
- `packages/opencode/src/i18n/en.ts`:加 `"cli.global.option.locale": "set the interface language (en, zh)"`
- `packages/opencode/src/i18n/zh.ts`:加 `"cli.global.option.locale": "设置界面语言 (en, zh)"`

## 验证
- `ocl --locale zh --help` → 帮助文本为中文
- `ocl -L zh session list` → 会话列表标题为中文
- `ocl --help` → 看到 --locale 选项说明
- `ocl --locale en --help` → 英文(显式覆盖)

## 不改的部分
- 不改 resolveLocale 优先级(env 仍最高优先)
- 不改 i18n 绑定逻辑
- TUI 的 locale 走它自己的 KV 持久化,不受此 CLI 参数影响(TUI 是交互式的,单独通过 language.switch 命令切换)
