# 方案:编译定制二进制 ocl,自动部署到 PATH

## 思路

用官方 `bun run build` 编译你的定制源码为单文件二进制,只把**产出二进制名**改成 `ocl`(区别官方 `opencode`),其余不动。一键脚本自动:编译 → 清理旧 launcher → 复制 `ocl.exe` 到 PATH。

- `opencode` → 官方版(npm)
- `ocl` → 你的定制版(编译产物),两命令共存
- 数据/配置目录仍是 `opencode` → **会话完全互通**

## 改动清单

### 1. `packages/opencode/script/build.ts` — 二进制命名(3 行)

```ts
// 第183行:产出名 opencode → ocl
outfile: `dist/${name}/bin/ocl`,
// 第184行(可选,纯展示):user-agent
execArgv: [`--user-agent=ocl/${Script.version}`, ...],
// 第203行:smoke test 路径同步
const binaryPath = `dist/${name}/bin/ocl`
```

### 2. 新增 `packages/opencode/script/deploy-ocl.ps1` — 一键编译+部署

```powershell
# 自动:① 编译当前平台 ② 清理旧 launcher ③ 复制 ocl.exe 到 npm bin 目录
$ErrorActionPreference = "Stop"
$repo = "E:\project\opencode"

# 编译(当前平台单二进制)
bun run --cwd "$repo\packages\opencode" build --single

# 定位产物
$binary = Get-ChildItem "$repo\packages\opencode\dist\*\bin\ocl.exe" | Select-Object -First 1
if (-not $binary) { throw "Build produced no ocl.exe" }

# 清理旧 launcher(sh/.cmd/.ps1),换二进制
$npmRoot = (npm config get prefix).Trim()
Remove-Item "$npmRoot\ocl", "$npmRoot\ocl.cmd", "$npmRoot\ocl.ps1" -ErrorAction SilentlyContinue
Copy-Item $binary.FullName "$npmRoot\ocl.exe" -Force

Write-Host "Deployed $($binary.FullName) -> $npmRoot\ocl.exe"
ocl --version
```

以后定制版更新流程就一条命令:
```powershell
powershell E:\project\opencode\packages\opencode\script\deploy-ocl.ps1
```

### 不改的部分
- ❌ npm 包名 / publish / postinstall — 不走 npm
- ❌ installation/upgrade 源 — 用 git rebase + deploy 脚本,不用 ocl upgrade
- ❌ 数据/配置目录、环境变量 — 全保持 opencode,保证互通

## 验证
1. `ocl --version` → 定制版本号(非 local)
2. `opencode --version` → 仍官方 1.17.15(共存)
3. `erp-java` 下跑 `ocl` → 看到与官方版相同的会话(互通)
